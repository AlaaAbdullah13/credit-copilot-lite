# Strict Guidelines for Credit Copilot Lite Development

You are acting as a Senior Python Engineer building "Credit Copilot Lite". Follow these strict domain and engineering rules without deviation:

## CORE ARCHITECTURE RULES
1. LAYERED ARCHITECTURE: Strictly separate Domain Logic (Domain models, rules, calculations) from Infrastructure (LLM, Vector DB, Web/API, Relational DB).
2. NO LEAKAGE: The domain layer (`src/domain/`) MUST NOT import any LLM, Vector DB, or Web framework libraries (e.g., LangChain, Chroma, FastAPI, Pydantic AI).
3. DETERMINISTIC CALCULATIONS: NEVER allow the LLM to calculate installments, DBR, age, or credit limits. All financial numbers must be computed by pure Python functions in `src/domain/calculations.py`.
4. GROUNDED RAG: The system must refuse to answer if document context is missing. Answer must always cite document chunks.
5. FAIRNESS BY DESIGN: Strip protected attributes (`gender`, `religion`, `marital_status`, `nationality`) via pure Python code BEFORE passing application data to LLM prompts or rule engines.
6. HUMAN-IN-THE-LOOP: Application offers remain `PENDING` until approved by a Credit Officer via API/Server enforcement.
7. SEPARATE STORES: Keep Policy documents (Trusted) and Customer Applications (Untrusted) in separate stores. Never index untrusted application data into the Policy Vector DB.

## CODING STANDARDS
- Language: Python 3.11+
- Package Manager: Poetry or `uv`
- Linter & Formatter: Ruff
- Testing: Pytest (Unit tests, Integration tests, Fairness test)
- API Framework: FastAPI with Pydantic v2
- Error Handling: Use explicit named domain exceptions (e.g., `PolicyEditionNotFound`, `UnverifiedExtraction`, `AuthorityLimitExceeded`).

## WORKFLOW
- Write clean, type-annotated code with docstrings.
- Always write corresponding unit tests when introducing new domain logic or pipelines.
